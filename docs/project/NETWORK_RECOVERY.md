# 네트워크 종료와 로비 복귀

## 동작 정책

- 내 연결이 끊기거나 방장이 종료되면 현재 세션을 정리하고 로컬 Lobby 씬을 다시 불러온다.
- 로비에서 끊겨도 씬을 다시 불러와 이전 방의 슬롯, 준비 상태, UI 참조를 초기화한다.
- 일반 참가자 한 명이 나가면 나머지 방은 유지하고 해당 플레이어만 제거한다.
- 방장 이전(Host Migration)과 진행 중 게임 복원은 지원하지 않는다. 종료 후 새 방 생성 또는 참가를 제공한다.
- 연결 종료 감지는 Fusion의 콜백과 타임아웃을 따른다. 케이블을 뽑은 순간과 콜백 발생 사이에 지연이 있을 수 있다.

## 책임 분리

`NetworkManager`는 연결 실패, disconnect, shutdown, host migration, 명시적 나가기를 하나의 정리 경로로 모은다. `SessionEnding`을 발행하고 Runner 종료와 참조/선택 캐시 정리를 마친 뒤 `SessionEnded`를 발행한다. 종료된 Runner는 재사용하지 않으며, Runner 전용 자식 오브젝트를 사용하여 Fusion의 오브젝트 파괴가 영속 Manager까지 제거하지 않게 한다.

`GameManager`는 위 이벤트를 구독하여 입력 차단 → Loading → 로컬 Lobby 씬 로드 → 입력·커서 초기화 → Lobby 상태 전환을 처리한다. 복귀 중에는 생성/참가 요청을 받지 않는다. `LobbyUI`는 저장된 종료 안내를 표시한다. 안내 UI는 기존 Canvas와 프로젝트 기본 한글 TMP 폰트를 사용해 생성하므로 Inspector 추가 연결은 필요하지 않다.

중복 종료 콜백은 같은 정리 작업을 공유한다. 이전 Runner의 늦은 접속 완료/씬 로드/종료 콜백은 새 세션을 변경하지 않는다. 이전 StartGame 응답이 늦어져도 종료 정리가 끝나면 다시 접속할 수 있다.

코드에서 정상적으로 방을 나갈 때는 `await NetworkManager.Instance.LeaveSessionAsync()`를 사용한다. 이 메서드는 Runner 정리까지 기다리며, 로컬 로비 씬 로드는 이후 GameManager에서 진행한다.

## 실제 네트워크 검증 절차

Host와 Client를 별도 프로세스로 실행한다. 다른 사용자와 방 이름이 겹치지 않는 환경을 사용한다.

| 상황 | 재현 | 기대 결과 |
| --- | --- | --- |
| 첫 접속 실패 | Host가 없는 상태에서 Client 참가 | 실패 안내, Lobby 복귀, 이후 Host를 실행하면 다시 참가 가능 |
| 로비에서 방장 종료 | 둘 다 Ready인 상태에서 Host 프로세스 종료 | Client가 Loading을 거쳐 Lobby로 복귀, 기존 슬롯 제거, 안내 표시 |
| 게임 중 방장 종료 | 맵에서 이동 중 Host 프로세스 강제 종료 | Client 입력 차단, 로비 복귀, 커서 표시, 새 방 생성/참가 가능 |
| Client 인터넷 단절 | 로비와 맵에서 각각 Client 네트워크 연결 차단 | Fusion이 단절을 감지한 뒤 Client 로비 복귀, Host는 남은 방 유지 |
| 씬 전환 중 단절 | 게임 시작 직후 Host 종료 또는 Client 연결 차단 | 복귀 후 늦은 맵 콜백으로 InGame에 재진입하지 않음 |
| 일반 참가자 이탈 | Host를 유지하고 Client 한 명 종료 | Host와 나머지 참가자는 방 유지, 이탈자 슬롯/캐릭터 제거 |
| 반복 실패·재접속 | 단절 → 복귀 → 재접속을 여러 번 반복 | 종료된 Runner 재사용 없음, 안내/복귀 중복 없음, 이전 선택/준비 상태 잔존 없음 |
| 정상 나가기 | 연결 중 LeaveSessionAsync 호출 | 정상 나가기 안내, 같은 정리·복귀 경로 수행 |

로비 복귀 이후 Create Room/Join Room 버튼, 안내 닫기, 플레이어 슬롯, 재입장 후 준비/게임 시작도 함께 확인한다.

## 이번 변경의 검증 범위

- 실제 Assembly-CSharp 프로젝트 C# 빌드 성공.
- 실제 GameManager/NetworkManager 소스를 연결한 임시 C# 모의 실행에서 중복 종료, 늦은 콜백, 최초 접속 실패, 로비/게임 중 복귀, 새 Runner 생성, 이전 StartGame 완료와 재접속의 경합을 확인했다.
- 모의 실행은 Unity/Fusion 대역을 사용했다. 실제 Photon 통신, Unity 씬 오브젝트 수명 및 화면 배치는 위 절차로 별도 검증이 필요하다.
